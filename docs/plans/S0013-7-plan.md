## 1. What exists today

* **The maps are full.** `_Func.__init__` (`targets/jit/common/compiler.py:344-351`) computes
  `lmask`, one bit per slot of a `_root` local (any, extern or exn hierarchy,
  `frontend/validate.py:157-159`), when the module has masks. `_Func.site` (`compiler.py:353-366`)
  marks `lmask | ops << L`, cut to `[0, L + keep)`, at **every** site; `ops` is the validator's
  operand mask in slot numbering (`gc.slot_bits`, `gc.py:127-137`). The comment at
  `compiler.py:342-343` says "liveness: step 7".
* **The masks.** The validator records a mask per safepoint pc of reachable code
  (`validate.py:606-608`; opcodes at `validate.py:153` plus every 0xFB opcode). Since the 6.2
  review (LESSONS 120) the bodies are walked again with masks on if a body turned `anyext` on
  (`validate.py:514-529`).
* **The format** (`gc.encode`/`decode`, `gc.py:140-170`, docstring `gc.py:6-9`; ARTIFACT.md part
  2): per site `u32 ret, u32 shift, u16 ret_at, u16 up, u32 map`; a pool of maps `u32 nslots` +
  `ceil(nslots/32)` words; map 0 = no reference slot. **There is no per-function bitmap**: a site
  does not name its function, so the walk cannot know which unmarked slots hold references.
  `decode` checks its length with an `assert` (`gc.py:169`), which `-O` removes.
* **The walk and the gatherer.** `walk._site` decodes a table lazily at the first walk
  (`walk.py:43-44`); `collect._gather` adds each frame's set bits as root runs
  (`collect.py:81-83`, `_ones` at `58-66`); `walk.check` validates every marked slot at every host
  call and libcall in check mode (`walk.py:101-119`). Nothing is nulled.
* **Consumers of `decode`:** `walk.py:44`, `tools/jit_dump.py:67` (`site[4]`), `tests/jit/test_stackmaps.py:26,158`,
  `tests/jit/test_exit_record.py:43`. The 3a refusal test: `tests/jit/test_walk.py:201`
  (`instance.py:966-967`).
* **After a site, a reference local's slot is read only by a later wasm `local.get`.** The lazy
  stack is flushed before every call (`flush`, `compiler.py:465-473`: every entry becomes `SLOT`):
  `call`, `call_indirect`, `call_ref`, `service` (`compiler.py:640-746`), `gc.struct_new`,
  `gc.throw`, the array services, the casts with an `is_subtype` call (`gc.py:358-401, 477-515,
  590-672`) and `gc.call_open` (`gc.py:674-698`). The only operands popped before a flush are
  `call_indirect`'s index and `call_ref`'s reference (`compiler.py:659,673`, `gc.py:681`), read
  by the call itself. So no `LOCAL` entry survives a site. This is what the pass needs; it is not
  asserted today (I5, 2.2).
* **Exception edges** in the code (`compiler.py:774-814`): inside a `try_table` every call's failure
  branch goes to the frame's `error` label, the pad (`compiler.py:782-784`); a pad that misses
  every clause jumps to `outer`, the enclosing pad or the epilogue (`compiler.py:813`); the cold
  ALLOC sites report to the `error` label they had (`gc.py:283-298`); `throw` jumps to `f.error`
  (`gc.py:400`).
* **Dead code** after an unconditional branch is skipped to its `end`/`else`
  (`compiler.py:833-842`): no site is emitted there.

## 2. Design

### 2.1 What "live" means here (brief item 1)
* A reference local (a `_root` local, parameters included) is **live at a site** if some path
  from the site's return point reads it before writing it: the normal return and, inside
  `try_table`s, the exceptional path to each pad. Operand slots keep the validator's mask (D3).
* **Two maps per site.** `refs`: every reference slot of the frame at the site (today's full map,
  `lmask | ops << L` cut to `L + keep`). `live`: the live reference locals plus the same operand
  bits. Always `live ⊆ refs`. The walk forwards `live` and writes 0 into `refs & ~live`.
* **Nulling is safe**: a dead slot is not read on any path before it is written (the definition;
  I5 makes it true of the machine code, not only of the wasm), so the walk may change it. Null is
  a valid word of every hierarchy, so after the walk every reference slot holds a valid word: I3
  holds for marked and unmarked slots alike.
* **Nulling is needed**: without it a dead slot keeps an offset into the old semispace, harmless
  while unmarked, but a later site that marks it by mistake would hand the collector a stale
  offset, turning a retention error into heap corruption. With nulling a slot wrongly **live** is
  retention only, and a slot wrongly **dead** reads null: a null check traps or a result is wrong,
  which stress and poison show. Neither reaches a stale offset. Every access is null-checked even
  for non-nullable types (S0013 3b decision B), so a wrongly nulled `(ref $t)` traps
  `NULL_REFERENCE` and never dereferences offset 0.
* **Poison** (`WABOROS_JIT_GC_POISON=1`) fills the old space after a collection: a slot neither
  forwarded nor nulled reads poison, in wasm or in the collector at a later marking (a bad header:
  collector trap, store lost). That catches M9.
* **Verify** (`_VERIFY=1`) digests the graph reachable from the runs before and after
  (`collect.py:149-151,180-185`). Dead slots are in neither digest and are nulled before the first;
  no change. Verify cannot see a wrong live set; stress, poison and the program's own reads can.
* **Check mode** (`WABOROS_JIT_WALK_CHECK=1`) also nulls dead slots, at every host call (D7): every
  dead set of the spec suite is then exercised at every host call and libcall, externref-only
  modules included, which never collect.

### 2.2 The analysis (brief item 2)
**Where.** `targets/jit/common/liveness.py` (new, about 130 lines), one function: the instruction
list, the slot of each reference local (`1 << self.slot[j]` for `_root` locals; v128 locals are
never references and take two slots, D41, so the sets are in slot numbering from the start), and
the site pcs (the keys of the validator's mask dict) in; `pc -> live bits` out. Called from
`_Func.__init__` beside `choose_pins` (`compiler.py:330`; D26: code generation stays one pass),
**only when `lmask` and `rm` are both non-empty** (D4).

**Pre-scan** (forward, once): match `block`/`loop`/`if`/`try_table` with their `else`/`end`, and
keep only what the pass reads: control, branches, `local.get/set/tee` of a reference local, site
pcs, `return`, `unreachable`, `throw`, `throw_ref`, tail calls. Everything else is skipped.

**Backward pass**, the live set a Python int:

| instruction | set before it (`out` = set after it) |
|---|---|
| `local.get j`, j a reference local | `out ∪ {j}` |
| `local.set j`, `local.tee j` | `out ∖ {j}` (tee reads its operand, not the local; Q3) |
| `end` of block, `if` or `try_table` | `out`, also the label's set (the continuation) |
| `else` | the set after the `if`'s `end` (the then-arm continues there) |
| `if` | then-arm start ∪ (else-arm start, or the set after `end` if there is no else) |
| `loop` | `out`, stored as the loop's head set (its label's set) |
| `br d` | `label(d)` (`∅` for the function's label: a return) |
| `br_if`, `br_on_null`, `br_on_non_null`, `br_on_cast`, `br_on_cast_fail` | `out ∪ label(d)` |
| `br_table` | the union of every target's label set |
| `return`, `unreachable`, `return_call`, `return_call_indirect`, `return_call_ref`, `throw`, `throw_ref` | `∅` |
| a site inside the body of one or more `try_table`s | then `∪ H` |

`H` is the union of the label sets of every clause of **every enclosing** `try_table` of the
function: a pad that misses jumps to the outer one (`compiler.py:813`). Every site in a body gets
`H`, services included; they cannot throw, and the surplus is retention only (D6).

**Recorded at a site pc:** the set before the instruction. A site instruction reads and writes no
local, so this is the set at its return point joined with `H` (Q3: "the set after it, joined with
the catch labels' sets"). All sites of one pc share it: `call_open`'s `is_subtype` call and its
call (`gc.py:687-695`), an allocation's cold ALLOC call, `br_on_cast`'s `is_subtype` call (the
label ∪ fall-through, as the table gives). **Unreachable code** after a branch is processed first
and then overwritten at the branch, so it never leaks into earlier points.

**Loop fixpoint** (D5): head sets start empty and the whole backward pass repeats until no head
set changes. Each pass is monotone in the head sets and the sets only grow, so it terminates: at
most `1 + loops × reference locals` passes, expected about nesting depth + 2 (the bound for
reducible flow graphs, which structured wasm is). The last pass's sets are recorded. **Cost** per
pass: O(kept instructions + `br_table` targets); passes and the pass's share of compile time are
measured in 7.4.

**LESSONS 120 (masks after bodies).** The pass is gated by the function's declared local types
(`lmask`), not by a module-level flag decided before the bodies, and reads `rm` only for where
the sites are, after `validate` (and its re-walk) has finished. Operand bits come from the masks
as today. An exnref with no declared type (`catch_all_ref`, the LESSONS 120 case) is an operand.

**Pinned locals** are `i32`/`i64` only (I1, asserted at `compiler.py:351`): never in `lmask`.
**exnref** locals are `_root` (D63): a caught exception kept in a local and read only in a handler
is live at the protected calls through `H`.

**I5 (new): no reference local's slot is read after a site except by a later wasm read.** This
makes the wasm-level analysis sound for the machine code; it follows from I2 (section 1). It is
asserted where it can be: in `_Func.site` no `LOCAL` or `ADDK` entry is left on `st` for the
inline sites, and the cold ALLOC sites are checked when `gc.alloc` queues them (about 3 lines);
it is stated in S0013 beside I1-I4. The popped `call_indirect`/`call_ref` operands are checked by
the reviewer by reading.

### 2.3 The map format (brief item 3; D1, D2)
* **Still `STACKMAPS`, the site record unchanged; each pool entry carries two bitmaps:** `u32
  nslots`, `ceil(nslots/32)` words of `refs` (today's map, same place), the same number of words
  of `live`. The pool is keyed by `(nslots, refs, live)`; map 0 still means "no reference slot".
  Reference-free modules keep byte-identical tables (no map, empty pool; CoreMark 108 sites, 1 736
  bytes, unchanged). Every module with a reference slot changes its table bytes.
* `decode` returns `(shift, ret_at, up, nslots, refs, live)`: index 4 keeps meaning "reference
  slots", so `jit_dump.py:67` and the exact-map tests of `test_stackmaps.py` still assert the full
  maps; new assertions read index 5.
* **ARTIFACT.md part 2 is amended; the context ABI (part 3) is not.** No context word, trampoline,
  backend method or D39 interface changes; aarch64 pays nothing (spec row 7).
* **Version (D2): v1 amended without a bump**, as `STACKMAPS` itself was (S0013 Q5, D56): no
  artifact file has been written (the serializer is ROADMAP "Next" (6)). The hard rule's test: a
  table in the 3a form with a map is **refused at instantiation** (`ValueError`); one without maps
  is the same in both forms and still runs. For that, instantiation decodes the table once with
  checks that raise instead of `assert` (exact length, map index ≤ `nmaps`, `live ⊆ refs` in every
  entry) and keeps the result in `walk_sites`; the walk's lazy decode goes. Cost measured (7).
* **D35**: code bytes unchanged everywhere; the table column changes exactly for the modules with
  a reference slot in some map (section 5).

### 2.4 How the walk nulls dead slots (brief item 4)
* **In `collect._gather`**, in the frame loop (`collect.py:81-83`): add the runs of `live` as roots
  (as `bits` today) and write 0 into the runs of `refs & ~live` (`_ones`, a `memset` per run).
  About 5 lines.
* **Ordering.** The world is stopped: nulling happens inside the ALLOC service's call, before
  `begin`/`roots` and before verify's first digest (`collect.py:144-151`). A dead slot is not a
  root, so nulling before or after copying gives the same heap; doing it while gathering keeps it
  in the one place that already visits every frame.
* **B1.** Nulled slots are inside `[0, nslots)` of each frame (`L + keep`); a wasm call's arguments
  (the callee's parameters) are above `keep`, in the callee's map. The collector's frame is never
  walked (`collect.py:82` asserts it).
* **`_free` (D61)** runs after `finish`: a host handle held only by a nulled `externref` slot is
  not met and is freed, which is correct (t25 tests it). Nested entries and other instances are
  walked as today. A store marked lost never resumes wasm (LESSONS 115).
* **Check mode** (`walk.check`): the same nulling, then validation of `refs` (dead slots are 0 by
  then), stronger than validating `live` only (D7). About 4 lines.
* **Outside a collection or check mode** nothing is nulled: a slot dead at a site where no walk
  happened keeps a word that did not move, still valid.

## 3. Spec text that contradicts the code or itself (to fix in S0013 with the step)

1. **"Per function, the bitmap of its reference-typed local slots"** ("Map content") and Q3's "(the
   per-function bitmap)": neither the format (`gc.py:6-9`, ARTIFACT.md) nor the walk has one, and
   the walk cannot find a site's function. D1 replaces it with a per-site `refs` map.
2. **The mutation "`local.tee` treated as a kill only"** (Test plan; Q3 "Testing": "`tee` as a pure
   kill") contradicts Q3's rule ("`local.set` and `local.tee` remove"). A tee **is** a pure kill;
   the lazy `LOCAL` entry it pushes is flushed before any site (I5). Replaced by mutants that do
   drop a live slot: M7 (local index for slot index) and M8 (the set taken one instruction late).
3. **"A mutation that marks a dead slot must pass every test"**: the exact live-set tests and "a
   dead reference slot reads null after a collection" (both in the Test plan) fail any
   over-marking by design. New text: "must pass every behavioural test; it fails only the
   exact-set, nulling and retention tests" (M10).
4. **"Skips the nulling and marks dead slots must be caught by poison"** is observable only if the
   marking is **inconsistent**: unmarked at a collecting site S1, marked at a later S2, no write
   between. Uniform over-marking is step 6's behaviour and passes everything (LESSONS 105). M9 is
   stated that way.
5. **"Inside a `try_table`, every call site and every `throw` also flows to each catch clause's
   label"**: the pads chain outward (`compiler.py:813`), so it is every *enclosing* `try_table`.
6. **Q3's instruction list** omits `return_call*` (empty), `br_on_null`/`br_on_non_null`,
   `br_on_cast(_fail)` (join with the target) and `if`/`else`: 2.2's table goes into Q3.
7. **"Operands … dead only when that consumer is `drop` (a stack simulation in the same pre-pass)"**
   and "runs only for functions with a reference-typed local or a reference operand at a site":
   the core has no stack-effect table (the validator has). D3 recommends not doing the operand
   part in this step; the gate becomes "a reference local and a site".
8. **"At most one pass per local and nesting level"**: replaced by 2.2's bound and the measured count.
9. **The step's fuzz acceptance is vacuous with the tool as it is.** `tools/fuzz.py`'s cross mode
   runs smith with `--reference-types-enabled false --gc-enabled false` and no imports
   (`tools/fuzz.py:65-72`): no reference local, so liveness never runs, and no heap, so stress and
   poison do nothing; and only `jit-x86_64` is in it. D9 proposes `--refs`; aarch64 fuzzing stays
   out (no QEMU fuzz harness).
10. **I3's wording** ("a reference slot dead at an earlier safepoint was nulled by that walk")
    holds only for walks that happen; 2.4's last item is added.

## 4. Decisions for the maintainer

**D1. How the walk learns which unmarked slots to null.**
* (a) **Two bitmaps per pool entry** (2.3): `refs` (today's map) and `live`; the 16-byte site record
  unchanged; reference-free modules keep identical tables; about +15 lines. The full maps of steps
  3a-6 stay in the data, so `live ⊆ refs` is checked at every decode and the existing exact-map
  tests keep their meaning.
* (b) **A second pool index per site** (`u32 refs_map`): 20-byte records, every module's table
  changes, CoreMark's included (+432 bytes); slightly better sharing.
* (c) **A per-function table of reference slots** and a function lookup by return address in the
  walk: a new section, a second search per frame, and operands could never be nulled.

**Recommend (a).** *Wasmtime:* a stack map lists only live slots, per pc a frame size and a bitmap
(`crates/environ/src/stack_map.rs:1-75`), and the tracer visits only those
(`runtime/store/gc.rs:764-800`). It needs no nulling because Cranelift has no fixed slot per
local: a value live across a safepoint gets a spill slot, reused once the value is dead
(`safepoints.rs:575-586`), and nothing reads it under the dead value's name. Our fixed slot per
local is what makes nulling necessary.

**D2. The artifact version and the refusal test.**
* (a) **v1 amended without a bump** (S0013 Q5, D56: no artifact file exists); the test: a 3a-form
  table with a map refused at instantiation by an eager, checked decode (2.3); instantiation cost
  measured.
* (b) **A format bump**: no field to bump in code until the serializer exists (ROADMAP "Next" (6)),
  so text only.

**Recommend (a).** *Wasmtime:* refuses any precompiled module whose engine version string differs
(a version byte and an exact string compare, `crates/wasmtime/src/engine/serialization.rs:39,105-124`),
so its stack-map layout carries no compatibility promise: "a loader refuses what it does not know".

**D3. Operand slots: Q3's "consumer is `drop`" rule.**
* (a) **As Q3.** The validator tracks, per pushed value, whether its consumer is `drop` (a list
  beside `vals`, updated at every push and pop; about +50 lines in code shared with `pyc`), or the
  core gets a stack-effect table (+80); the masks get a live variant and the walk nulls dead
  operand slots too.
* (b) **Not in step 7**: operands keep the validator's mask. The cost is retention of a value below
  a call that is later dropped, only until the `drop` runs (after it the position holds another
  value or none); compilers rarely leave a reference under a call only to drop it. Recorded as a
  narrowing of Q3 in the decision.

**Recommend (b)**; (a) would be a sub-step 7.2b of about +50 / +40 with its own mutant.
*Wasmtime:* SSA gives Cranelift this for free (a dropped value has no use), but it treats every
block-call argument as live (`safepoints.rs:222-224`): our "a value that leaves its block through
a branch or `end` counts as live".

**D4. Where the pass runs, and its gate.**
* (a) **The core**, `common/liveness.py`, from `_Func.__init__`, only for a function with a
  reference local **and** a site (Q3's decision); it runs again on a far-mode retry (rare; measured).
* (b) **The validator**: a forward walk, so a second, backward walk anyway; it would run for `pyc`
  too, and twice when the 6.2 re-walk happens.

**Recommend (a).** *Wasmtime:* in the compiler after translation: `FunctionBuilder` runs the
liveness and the spiller (`safepoints.rs:494-520, 642-695`) on values the translator declared as
needing stack maps (wasm locals at `crates/cranelift/src/translate/func_translator.rs:174-176, 274`),
never in the validator.

**D5. The loop fixpoint.**
* (a) **Repeat the whole backward pass** until no loop's head set changes (2.2): the simplest, no
  CFG; the bound measured.
* (b) **Iterate each loop locally**, recursively: fewer instructions per round, but inner loops are
  re-iterated on each outer round (worst case exponential in depth), more code.
* (c) **A worklist over a basic-block graph**, Cranelift's shape: a CFG we do not otherwise build
  (ARCHITECTURE.md: structured, no CFG).

**Recommend (a)**; (c) is the fallback if a real module shows a pathological pass count.
*Wasmtime:* (c), blocks seeded in post-order so an acyclic graph takes one pass, a block whose
live-in set grows re-queues its predecessors (`safepoints.rs:205-220, 494-520`).

**D6. Exception edges.**
* (a) **Every site in the body of any enclosing `try_table` joins `H`**, the clause labels of all
  enclosing `try_table`s: sound and simple; services and `is_subtype` calls cannot raise status 14,
  so their extra bits are retention only.
* (b) **Only call and throw sites, only up to the first `catch_all`** on the pad chain: precise, about
  15 more lines, and a second notion of "which sites throw" to keep in step with the lowering.

**Recommend (a).** *Wasmtime:* exception-table destinations are successors of `try_call`, their
block-call arguments uses "that logically happen after the instruction" (`safepoints.rs:427-443`);
GC references are rejected as exception-context values (`safepoints.rs:465-480`), so a handler sees
references only through locals and its arguments, as ours does.

**D7. Check mode nulls dead slots.**
* (a) **Yes**: `WABOROS_JIT_WALK_CHECK=1` nulls dead slots at every host call and libcall, then
  validates every reference slot. CI's whole-suite walk-check runs (both architectures) then test
  every dead set at every host call, modules that never collect included. About 4 lines.
* (b) **No**: only collections null, so dead sets are exercised only in GC stores under stress.

**Recommend (a).** *Wasmtime:* nothing comparable (it never nulls).

**D8. A per-function switch for bisecting.**
* (a) **`WABOROS_JIT_NOLIVE=all|i,j,…`**, shaped like `WABOROS_JIT_NOPIN` (`compiler.py:283`):
  `live = refs` (the step-6 maps) for the named functions; no code byte changes. It is the
  CLAUDE.md way to debug (mix known-good and new per function and bisect), the same-tree control
  of 7.4's measurements and M10's control. 3 lines; TESTING.md lists it.
* (b) **None**: bisect by editing the source.

**Recommend (a).** *Wasmtime:* not checked.

**D9. Fuzzing references in step 7.**
* (a) **`tools/fuzz.py --refs`** (about 4 lines): smith's reference types on in the cross mode; with
  D7 the run tests liveness on externref/funcref locals and table services. GC in the fuzzer stays
  step 8's.
* (b) **Leave it to step 8**: the row's fuzz acceptance then means only "code unchanged" (section 3,
  item 9).

**Recommend (a).** *Wasmtime:* not checked.

## 5. Identity (D35; brief item 7)
**Expectation** on `tools/jit_dump.py`, column `c` (the digest of code and everything else) and
column `s` (the `STACKMAPS` digest):

| sub-step | `c` may change | `s` may change | must not change |
|---|---|---|---|
| 7.1 | none | exactly the modules with a non-zero map in the base (the new pool form) | `c` everywhere; `s` of every module without a reference map, CoreMark included |
| 7.2 | none | a subset of 7.1's set: modules with a function that has a reference local and a site | `c` everywhere; `s` of every other module against 7.1 |
| 7.3 | none | none (tools and tests only) | everything |

**Proof** (as step 6, with LESSONS 98, 114, 121):
1. Two **fresh, empty** scratch directories: `git archive` of the base into one, of HEAD plus the
   working-tree diff (`src tests tools poc/in`) into the other; the spec cache linked into both;
   equal module counts checked before any diff.
2. Each run *inside* its copy with `PYTHONPATH=<copy>/src:<copy>`, the same command printing
   `waboros.__file__` (the editable install would otherwise run the checkout's package).
3. `--target jit-x86_64` and `jit-aarch64`, `WABOROS_JIT_BOUNDS=guard` and `=explicit`: 8 lists.
4. **7.1's set is the base's own decode** ("a site with non-zero bits", which `jit_dump` already
   counts): the `s` diff must equal it **both ways**, and must include named members (a

## 11. Risks, what this step does NOT do, and the invariants relied on (brief item 8)

**Risks**
* **A missed edge drops a live slot.** The result is a null (a trap or a wrong result), never a
  stale offset: nulling makes it visible and contained. One test and one mutant per edge kind
  (section 6); D7 tests every dead set of the suite at every host call.
* **A lowering that reads a local's slot after its own site** would break I5 silently: the
  assertion covers the stack, the reviewer the popped operands, and future lowerings inherit the
  assertion.
* **Fixpoint cost on deep loop nests**: bounded and measured; D5 (c) is the fallback, decided with
  the measurement.
* **The format change** touches every module with references (`s` column): data only, with the
  refusal test, no serializer yet.
* **Retention left by D3 (b)**: a reference below a call and later dropped is kept until the drop.
* **No new deviation from Wasmtime's results**: liveness only changes when memory is reclaimed;
  Wasmtime's own liveness is SSA-precise, so ours retains at least as much (operands, D3; joins, D6).

**Not doing**: no operand liveness (D3 (b)); no final review, GC in the fuzzer or fuzz triage (step
8); no machine-code change on either architecture, no context ABI or D39 change, no backend file
touched; no change to `pyc`, the validator, the collector module, `gcverify` or the runner; no
artifact serializer, no version bump (D2); no per-OS code (D47 rows: none); no optimisation of the
walk or the pass without a measurement.

**Invariants relied on**
* **I1** references never pinned (`compiler.py:351`); **I2** the operand stack in slots at every
  call; **I3** marked slots hold valid words, now every reference slot after a walk; **I4** nothing
  derived from a reference kept in a register across a call; **I5 (new)** a reference local's slot
  is read after a site only by a later wasm read (2.2).
* B1: a frame's map covers `[0, L + keep)`; a nested frame starts above `keep`.
* The world is stopped during a collection (one thread per store); a lost store never resumes wasm.
* Null (0) is a valid word in every hierarchy, and every access null-checks (3b decision B).
* Reference words are u32 offsets zero-extended in u64 slots (LESSONS 5); the walk reads and writes
  whole 64-bit slots.
* Sites read and write no local, so the set before a site instruction is the set at its return
  point.
