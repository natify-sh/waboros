Where it differs, S0013 "Step 5 decisions" wins: D3 chose Wasmtime's moving-boundary semispaces (not the fixed halves of section 1.5), D1 keeps instantiation non-collecting, D7 defers alloc, externref host values are freed, and the 5.2 review added three obligations for 5.3.

# S0013 step 5: the copying collector, implementation plan (for approval)

Base: branch `gc`, HEAD f3ae060 (step 5.0, B1, done). Sources: S0013 (Roots and the collector, Q2, Q4,
Q11, the three "Carried over" paragraphs), D54, D56, D57, ARTIFACT.md part 3, R3, LESSONS 98-110, the code
in `jit/common/{gc,heap,walk,instance,compiler,context}.py`, the reviewer's scratch mover (`review5/mover.py`).

What the mover settled (reused as findings, not as code). Its root set was enough for all of `gc/` and
`exceptions/` on both JITs: frames by `walk.walk`; defined globals only (an imported global through its
owner's word); tables visited once by identity, any/extern hierarchy by `_root(mod, ttypes[t])`; passive
segments by `_root(elem type)`; `gc_handles` plus a rekeyed `gcrefs` (B5: `NOREKEY=1` breaks); arena
payloads by tag parameter types. `MOVE_SVC=1` reproduced B2/B3 (the services read operands before
allocating). Today's tests rewrite only 11 marked slots in the whole of `gc/` and `exceptions/`, so
coverage has to come from new targeted tests.

## 1. Shape

### 1.1 The module: `src/waboros/runtime/gc/collector.wat` + committed `collector.wasm` (D54, WAT)
WAT, not C. The estimate is about 200 lines, inside "small", so D54's C rule (ziglang, sanitizer build,
stack placement) does not apply. If the WAT grows past ~400 lines, stop and report.

* Imports: `(import "gc" "heap" (memory 1))`, the store's hidden memory, nothing else. No data
  segments, no `memory.grow`. Instructions are core MVP plus `memory.copy` (bulk memory). No SIMD, no
  GC, no exceptions, no tail calls, no `call_indirect`. State between phases is kept in mutable module
  globals (one instance per store, so this is per-store state).
* Exports (decision M3 below; this replaces the one `collect` that the spec names):
  * `begin(from_lo, from_hi, to_lo, to_hi: i32)`: sets the spaces; `copy = scan = to_lo`.
  * `roots(n: i32)`: forwards the u64 words `ROOTS[0..n)` in place. It skips 0, i31 (`x1`) and host
    words (`10`), and also a word already in `[to_lo, copy)` (a duplicate root). It traps on a
    nonzero high half, a word with `w & 7` not zero, or a word outside both spaces.
  * `finish() -> i32`: the Cheney scan from `scan` to `copy`, forwarding every traced field. Returns
    the new cursor.
  * `is_subtype(q_tid: i64, t_tid: i64) -> i32`: see 1.6.
* `forward(w)`: if bit 0 of the bits word `w+4` is set, return the u32 at `w`. Otherwise check that
  the record offset lies in `[TYPES, TID_MAP)` and that its kind is 1 or 2. Size: a struct's `R_SIZE`,
  or for an array `(16 + len*es + 7) & ~7`. Trap if `copy + size > to_hi`, then `memory.copy`, then
  write `{copy, 1}` into the old header and bump `copy`. A malformed heap traps with `unreachable`; it
  never writes outside the memory. No interrupt poll fires: see 1.5.
* Header page regions (ARTIFACT part 3 changes):
  * 0-7: null.
  * 8: cursor; 12: limit.
  * 16-63: reserved.
  * **`[4 KiB, 64 KiB)`: `ROOTS`, the roots batch buffer** of 7 680 u64 words. It is in the header
    page, which is committed at heap creation and never holds an object or record.
  * Type-info area: records `[64 KiB, 60 MiB)`, and the **tid map `[60 MiB, 64 MiB)`** (2^20 u32
    entries, added in 5.6).
* Loading: `importlib.resources.files("waboros.runtime") / "gc/collector.wasm"`. `pyproject.toml`
  `package-data` gains `"runtime/gc/*.wasm"`. No `__init__.py` in `runtime/gc/`, so it is a data
  directory and a Python package named `gc` never exists.
* **Match test** (`tests/test_collector_module.py`): `tests/watcache.wat2wasm(collector.wat)` must
  equal the committed bytes. Spec contradiction: S0013 says the assembler is `wasm-tools`, but
  watcache uses wasmtime-py's `wat2wasm`. Fix the text to match the code; that gives one assembler,
  pinned through wasmtime-py 50.0.1.
  * The `wat` crate is pure Rust, so the same text gives the same bytes on every OS. The test runs
    wherever wasmtime is installed and skips without it. A wasmtime bump that changes the bytes
    means regenerating and reviewing the diff. This settles D54's "same bytes on every OS" question
    for WAT.
  * The same test checks the structure with our decoder: imports, the export names, no data, no
    `memory.grow`, opcodes in an allowed list.

### 1.2 Who compiles and runs it
* **When.** The collector is compiled and instantiated when the store's `GcHeap` is created (the first
  instance whose layout has `heap`). The compiled code is cached per process by (target, bounds
  flags). It is compiled by the target of that first GC instance: `Compiled` gains `target: str`,
  which `compile_module` already receives. One path serves `collect` and `is_subtype`.
* **Instance.** A `CollectorInstance(JitInstance)` in the **same store**. It has to be: `is_subtype`
  is reached by `call_record`, and the callee prologue checks the store's own `VSTACK_LIMIT`. It
  imports `heap.mem`, so `mem.users` publishes size changes to it too.
  * It overrides `interrupt()` with a no-op. `StoreState.interrupt` would otherwise set its
    `INTERRUPT` word and a loop poll would cut a copy in half. Its words are 0, so its polls never
    fire.
  * It stays in `store.instances`, so `NSTACK_LIMIT` updates (instance.py:767) and the walk's code
    ranges include it.
* **Entering `collect`.** A nested JIT entry, `CollectorInstance.call` (the normal `Instance.call`),
  from the allocating service's callback. `_host` has already set `st.vsp = slots + 8·max(n, m)`, so
  the collector's frame starts above the service's slots. That is exactly the B1 rule step 5.0
  enforced in the core (`site`: `hi <= keep`).
* **Stack limit.** Before each entry, Python sets the collector context's `NSTACK_LIMIT` to the
  thread's real stack low end plus 64 KiB (`_stack_low()`), or `nlimit − 256 KiB` if the low end is
  unknown. Without this, an allocation near the wasm stack budget would trap `STACK_OVERFLOW` in the
  collector's prologue: Python's callback frames already sit below `nlimit`. A prologue trap happens
  before anything moves, so it is safe, but it would be a deviation from Wasmtime.
* **No collection from `EXN_REFILL`.** `EXN_REFILL` does not set `st.vsp`, so it must never collect.
  Step 5 keeps it arena-only. `collect()` asserts `st.vsp > exit.frame` and `exit.sp != 0`, which
  catches any caller that did not set the frame base.

### 1.3 Python: `jit/common/collect.py` (new, ~180 lines), gather and scatter
`collect(store, st, request)`:
1. Refuse: `st.lost` set; `heap.nocollect` > 0 (instantiation); not inside a host call.
2. Verify mode: build the pre-collection digest (1.4).
3. Commit the to-space `[to_lo, to_lo + S)`.
4. Gather the root **runs**: native u64 ranges `(addr, count)` and Python lists, in a fixed order.
5. Set `st.lost = "GC interrupted"` (critical section). Call `begin`. Per batch of ≤ 7 680 words:
   `memmove` into `ROOTS`, call `roots(n)`, `memmove` back and scatter. Call `finish`.
6. Switch the active space: cursor = result, limit by the policy (1.5). Rebuild `gcrefs` (B5).
   Clear `st.lost`.
7. Poison the old used part, if poison is on. Grow by the policy. Verify the form and compare the
   digest.

**An asynchronous exception in step 5** (KeyboardInterrupt in a scatter): a `finally` finishes the
scatter and then re-raises. A second interruption leaves `st.lost` set, and every later `Instance.call`
of the store raises `RuntimeError(st.lost)`, the same pattern as `guard.LOST`. A collector trap
(malformed heap) does the same. Cost: one attribute test per entry.

**Root classes** (from every `Instance` in `store.instances` with a `module`; GC or not):

| class | where | how gathered |
|---|---|---|
| frames | `walk.walk(store, st, tramp)` from the exit record, across nested entries and every instance, `tail_switch` restore frames, host thunks | marked slots `base + 8k` (runs of adjacent bits merged) |
| globals | `inst.gaddr[g]` where `_root(mod, gtypes[g])`; imported ones are the owner's word | dedup by address set (host-made cells included) |
| tables | every distinct `Table` with `refs` true | one range `(addressof(buf), size)`; dedup by `id` |
| passive element segments | `inst.elems[s]` (dropped = `[]`, active emptied) with `_root(mod, elem_info[s][2])` | Python list, rewritten in place (`items[:] = …`) |
| host handles | `st.gc_handles` | Python list; afterwards `gcrefs = {gc_handles[r.index]: r for r in gcrefs.values()}` (B5: an old word never names a new object at a reused offset) |
| arena payloads (until step 6, ~25 lines) | every `st.chunks` object up to `st.exn[1]`, by `st.tags[tid].params` with `_root(tag.module, p)` | native words |
| pending exception | arena address until step 6, not a heap word | none in step 5 |
| constant expressions / instantiation | never collect (`heap.nocollect` counter around `JitInstance.__init__` up to `start`) | none; enforced by refusal |
| runtime | services read operands after collecting (5.4); `to_raw` happens just before the entry and `from_raw` just after | none |

* **B6, element types.** `Table` gains `refs: bool`, set by its creator: `JitInstance` from
  `_root(mod, ttypes[i])`, and False for host-made funcref tables. funcref and exnref words look like
  offsets, so they are never sent.
* **Duplicates are harmless** because the module leaves to-space words alone. Dedup by identity and
  address is only there to save time. This answers the reviewer's "each root visited once, or a
  from-space test": both.
* **Instances without GC** that hold internalized objects in `externref` globals, tables or segments
  are visited, because the loop covers every instance. Their frames are already mapped (externref
  slots since 3a).
* **B6, half-built instances.** `Instance.__init__` registers the instance before its tables and
  segments exist. So: (a) `tables`, `elems`, `gaddr` and `cells` are initialized to `[]` before
  `super().__init__`, and a gather never sees a missing attribute; (b) instantiation does not collect
  (enforced as above); (c) an instance whose instantiation **trapped** after writing its functions
  into an imported table stays a root source. Its functions may still be called and read its anyref
  globals. 5.5 has a test for this.

### 1.4 Verify switch: `jit/common/gcverify.py` (~140 lines, test-only, independent of the module)
* It works over a `memoryview` of the heap bytes plus the record table, so it also checks the heap
  images in the module's own tests (5.2).
* **Form**: walk the new active space object by object: the record is in `heap.offsets`, the bits are
  0, the size comes from the record. Every traced field and every root is 0, an i31, a host word
  with a live handle, or an object start of the new space.
* **Digest**: SHA-256 over a BFS from the roots in gather order. It covers each root's kind, the
  record offset (records never move), the array length, the object bytes with reference fields
  replaced by BFS ordinals, i31 values and host handle numbers. The digest before must equal the
  digest after.

### 1.5 Semispaces, growth, switches (`heap.py`)
* **Layout.** Fixed A = `[64 MiB, 2 GiB+32 MiB)` and B = `[2 GiB+32 MiB, 4 GiB)`, as the spec says.
  Each is committed from its start to *S*. This needs `Reservation.commit_range(lo, hi)` (~10 lines
  in `execmem.py`, over the existing per-OS `_commit`, which already takes any start; no new per-OS
  code, D47). `size_bytes` is the highest committed end and never shrinks.
* **B7.** `is_object(w)` tests the **active** `[lo, cursor)`; `walk.valid` follows it.
  * `grow()` becomes `room(r, collect)`. It returns only when `cursor + r <= limit`, otherwise it
    raises `MemoryError("GC heap out of memory")`, so the code's retry loop cannot spin.
  * `alloc(size)` (instantiation, constant expressions) is `room(size, collect=False)` plus a bump.
* **Policy** (D2 below). The first commit of an empty heap does not collect. When full: collect, then
  with live *L* and request *r*:
  * if `L + r > S_max`: out of memory (an `r > S_max` fails before collecting);
  * if `2(L+r) > S`: `S' = min(S_max, max(2S, 2(L+r)))`, rounded to 64 KiB, committed in the active
    half (the other half at its next use).
  * `S0` is 1 MiB. `S_max = 2 GiB − 32 MiB` (`gc.S_MAX`, which tests lower with monkeypatch). No
    shrinking and no decommit.
* **Stress** (`WABOROS_JIT_GC_STRESS=1`): every `room(collect=True)` collects and then sets
  `limit = cursor + r`, exact room, so the retry succeeds and the next inline allocation is slow
  again. Every non-collecting allocation sets `limit = cursor` afterwards. The result: every
  allocation that may collect does collect.
* **Poison** (`=1`, already used for fresh space): also fills the from-space's used part after each
  collection and the active space's free `[cursor, limit)`.
* **Verify** (`=1`): 1.4.

### 1.6 `is_subtype` and the removal of FUNC_SUBTYPE (5.6)
* **Records.** Type-info records for function types (kind 3, `final`, depth, size 0, nrefs 0,
  display). They are written for every function type of a GC module at its instantiation, together
  with `tidmap[type_id] = record` at `60 MiB + 4·tid` (cap 2^20 process-wide ids; past it, "GC type
  area exhausted").
  * Correct because any proper subtype of a type is declared in a GC module of the same store, which
    registered it. An unregistered q, or a q at or past the cap, answers 0 (equality was already
    tested inline).
* **Module:** `is_subtype(q, t)` checks `q < cap`, looks up `rq = map[q]` and `rt = map[t]`, returns 0
  if either is missing, then does the display test (`depth(rq) >= depth(rt)` and
  `display(rq)[depth(rt)] == rt`), about 15 lines. Passing the target as a tid instead of a record
  means **no RTT words for function types**, so modules keep their RTT numbering.
* **Core (`gc.subtype`, `call_open`, `ref_test`).**
  1. `rec`: load the record's type id with a **new D39 method `func_type(dst, rec)`** (word 1 of a
     function record; D1 below).
  2. Compare it with the signature word; equal → hit.
  3. For a final target, a mismatch → fail, and no call is made. A `ref.test`/`ref.cast` of a funcref
     to a final concrete type loses its safepoint.
  4. For a non-final target: the record in slot h, `q` at h+1, `t` at h+2. Call
     `call_record(f, layout.subtype(), L+h+1)`; the site is `fn.site(pc, L+h+1, h+1, top)`; the result
     is at h+1.
  The record kept at h stays below the callee's frame (B1, LESSONS 108, LESSONS 110).
* **Context.** GC group word 7 (`FUNC_SUBTYPE`) becomes reserved, zero. A 3-word record
  `IS_SUBTYPE {code, tid 0, collector ctx}` is appended **after the RTT words** in every GC module, so
  no existing word moves. Only modules that reach a function-subtype site change code (D35).
* **Removed:** the `_func_subtype` service and its registration. The D57 "Deviation from D25" is
  closed. Python's `func_subtype` stays for the host boundary's type check, which is not JIT
  computation.

## 2. Decisions for the maintainer

**D1. B4: do the array services collect?**
* (a) yes, `ALLOC`, `ARRAY_NEW`, `ARRAY_NEW_DATA`, `ARRAY_NEW_ELEM`;
* (b) no; they grow.

(b) costs nothing now, but a loop of `array.new` of `i32` that drops every result runs out of heap,
which is a wrong result against Wasmtime. (a) costs about 50 src lines: GC services get the live slot
view (`_host(..., live=True)` passes the ctypes array, not a copy) and read reference operands after
`room()`; plus a test per service under stress.

**Recommend (a)** (the orchestrator's view too). Instantiation and constant expressions stay
non-collecting. `ARRAY_FILL`/`INIT_*` allocate nothing.

Spec fix: "Roots and the collector" and "safepoints" say "Collections happen only in the allocation
service". Replace with "only in the GC group's allocating services (ALLOC, ARRAY_NEW, ARRAY_NEW_DATA,
ARRAY_NEW_ELEM); never during instantiation".

**D2. Growth policy.**
* (a) the spec's: collect when full, double when more than half is live, `S0` 1 MiB, never shrink;
* (b) grow without collecting while *S* < 8 MiB (fewer early collections, more memory);
* (c) a separate large-object rule.

**Recommend (a)**, unchanged, measured in 5.7 (pause, churn, the Kotlin program). Plus: no collection
for the very first commit; `r > S_max` fails at once. The 2 GiB − 32 MiB live limit is recorded as a
deviation (Q2, already accepted). `pyc`'s ~2× memory per array element is recorded beside it, as
carried over from step 2.

**D3. Semispace B and the "hole" (D57).**
* (a) Fixed A/B as specified. While B is in use, `[A's committed end, 2 GiB+32 MiB)` is uncommitted
  below `size_bytes`. In explicit mode only a stale or corrupt reference reaches it, and the process
  faults (Q8 accepted this). In guard mode the heap reservation is registered, so it traps.
  +10 lines (`commit_range`).
* (b) Commit the hole: up to ~2 GiB of commit charge per store (Windows paging file, strict
  overcommit, Android). No.
* (c) Adjacent halves whose boundary moves with *S* (no hole). A non-collecting growth while the upper
  half is active forces a third position or a second copy; ~+60 lines of placement logic. The live
  limit falls to ~1.3 GiB in the worst case.

**Recommend (a)**, recorded in D57/D58 as decided; poison and verify find stale references in tests
before they can fault.

**D4. How the collector is invoked.**
* (a) `CollectorInstance.call` (a normal nested entry, ~7 µs Python per entry, 3 entries per
  collection plus 1 per extra batch);
* (b) a bare ctypes call to the entry, skipping `Instance.call`'s bookkeeping: it duplicates
  `store.enter`/`active`/`vsp` logic, no;
* (c) JIT code calls `collect` directly: impossible, the roots come from Python first.

**Recommend (a)**, with the B1 rule (enforced since 5.0), the collector's own stack limit (1.2) and
the no-op `interrupt`.

**D5. Cheney against depth-first (Q2).** Two builds: the committed Cheney `collector.wat`, and a
**scratch** variant (not in the tree) with a bounded explicit stack (7 168 u32 entries in the upper
part of the roots page) that falls back to the Cheney sweep when it overflows. Measured in one
session, alternated, medians, guard and explicit:
* `tools/bench_gc.py` new loops, each measured after 5 forced collections: walk of a 10⁶-node list,
  pre-order traversal of a 2²⁰-node tree, scan of a reference array of 10⁶; binary-trees (WAT, as the
  Test plan names it); the pause per collection with 10⁶ live objects;
* the 4b Kotlin program, whole run (`tools/run_corpus.py`, its case loop).

Rule (Q2): depth-first replaces Cheney only if it gains beyond the round-to-round spread on the
microbenchmarks **and** on the Kotlin run. Only the chosen `.wasm` is committed. The result goes into
BENCHMARKS.md and D58. A list lays out the same way in both orders, so expect differences mainly on
trees.

**D6. FUNC_SUBTYPE removal** (1.6). It needs
* (i) a **D39 amendment**: `func_type(dst, rec)` in both backends (~6 lines each: `mov dst,[rec+8]` /
  `ldr dst,[rec,#8]`; no existing module's code changes);
* (ii) the context change: word 7 reserved, `IS_SUBTYPE` record after the RTTs;
* (iii) the tid → record map: a direct map (cap 2^20 ids, ~5 WAT + 8 Python lines) **recommended**,
  against an open-addressing hash (no cap, ~40 lines in WAT and Python, rehash into new type-area
  space).

There is no way around (i): the module cannot read native memory, and no D39 method loads from an
address held in a register.

**D7. The `alloc` export** (Q4 and RUNTIME-MODULES item 2 decided `collect`, `is_subtype`, `alloc`).
* (a) As decided: every Python-side allocation (constant expressions, array services) enters the
  module. That is +~7 µs per allocation. Instantiating 10⁴ allocating constants costs +70 ms, and
  `array.new` services roughly double in cost.
* (b) Export it but keep Python's bump: two allocators, against the intent.
* (c) **Defer `alloc` to ROADMAP item 6** (the C loader and the instantiation module), its first
  consumer outside Python. In step 5, Python's `GcHeap.alloc` is the runtime allocator and mirrors the
  inline bump (3 lines).

**Recommend (c)** (CLAUDE.md: no abstraction before its second real use); fall back to (a) if the
maintainer keeps it.

**M3. Export names.** `begin`/`roots`/`finish` replace a single `collect`, because the buffer is
bounded (a table may hold 10⁷ elements) and batches need state between calls. Alternative: one
`collect` taking every root in one buffer. That needs an unbounded region outside both spaces, and
there is none. **Recommend the three phases.** RUNTIME-MODULES.md and S0013 Q4 text updated.

## 3. Fixes folded in

* **B2** `_array_new`: read `n` and `ti`, `room(size)`, allocate, then read the value `a[0] | a[1] << 64`
  from the live slots (the slot is a root rewritten in place).
* **B3** `_array_elem`: bounds first (`o + n <= len(elems[seg])`, the trap order of LESSONS 102), then
  `room`, then allocate, then read `self.elems[seg][o:o+n]`. `_array_data` keeps its order (no
  references). `GcHeap.new_array` loses `vals=` captured before allocation; it allocates first, then
  writes.
* **B5** the `gcrefs` rebuild in `collect()` (1.3).
* **B6** `Table.refs`; attributes initialized before registration; the `nocollect` counter; failed
  instantiations stay root sources (1.3).
* **B7** the active-space `is_object`/`valid`; `room` returns with room or raises; the stress limit is
  `cursor + r`, never `cursor`, after a service.
* **EXN_REFILL** never collects in step 5 (the arena is outside the heap); `collect()` asserts that a
  host call set the frame base (1.2); ARTIFACT's sentence stays.

## 5. Tests

  * byte match and structure;
  * random heap images (structs with mixed fields, ref arrays, i31 and host words, cycles, sharing,
    duplicate roots, multi-batch roots) collected by the module on **Wasmtime and the machine's JIT**

  * `is_subtype` on built records (depth 0, 1 and 3; unregistered q; q at or past the cap).
* `tests/jit/test_gc_collect.py` (5.3):
  * the growth sequence: S doubles at more than half live and never shrinks;
  * out of memory with `gc.S_MAX` lowered (live just under succeeds, just over raises
    `MemoryError("GC heap out of memory")`);
  * the A↔B flip and `is_object`;
  * the `st.lost` refusal after an injected exception in the scatter;
  * `store.interrupt()` during a collection does not cut it;
  * allocation at maximum recursion depth collects, with no `STACK_OVERFLOW`;
  * a collection during instantiation is refused (`nocollect`).
* `tests/jit/test_gc_moving.py` (5.4, under stress + poison + verify; the reviewer's list). Each test
  checks values and `ref.eq` identities after collections:
  * operands below an allocation (`struct.new` field, `array.new` value);
  * callee parameters; `return_call` and a cross-instance tail call (restore frame);
  * a non-final `call_indirect`;
  * v128 operands and locals below references; block parameters across an allocating call;
  * `array.new_fixed` with reference elements; churn;
  * host↔wasm nesting 3 deep with references in every frame;
  * a host handle kept across collections and passed back (B5);
  * **one test per allocating service that collects** (B2, B3, B4, with the reference value or
    segment item checked).
* `tests/jit/test_gc_roots.py` (5.5), one test per root class with the reference held only there:
  * a reference local; a parameter; a defined global; an imported global;
  * a table imported by two instances (visited once);
  * a passive segment;
  * an arena payload (`anyref` tag parameter, caught exnref kept in a local or global, rethrown after
    collections);
  * the outer frames of a nested entry; a frame of another instance; a host-thunk frame;
  * an `externref` global, table and local of a **module with no GC types** holding an internalized
    object;
  * **the failed-instantiation case** (elem written into an imported table, then a data segment

## 8. Risks, and what this plan does NOT do

**Risks**
* **The module compiled by our JIT is trusted for every heap** (R3). Mitigations: differential runs
  of the module on Wasmtime, the verifier (independent Python), poison, the mutations, and the ISA
  gate including the collector.
* **Atomicity.** An asynchronous exception or a trap mid-collection is detected (`st.lost`) and the
  store refuses further calls. Detection only: the store is lost, not repaired. PyPy has the same
  caveat as D51.
* **The explicit-mode hole** (D3 (a)): a stale reference crashes instead of trapping.
* **Gather cost.** Frames cost 0.5 µs plus 0.1-0.2 µs per slot (measured), so deep recursion makes
  collections slower. Large tables are one `memmove` per batch. Handles grow until phase 6 (Q10), and
  their rekey is O(handles) per collection.
* **Stress-mode CI time**: `gc` and `exceptions` only, not the whole suite. The whole suite under
  stress is step 7's.
* **Process-wide tid cap** of 2^20 for function-subtype checks (D6 (iii)).
* **The collector's own `NSTACK_LIMIT`** relies on the thread's stack bounds (`_stack_low`). Where
  they are unknown, the fallback is a fixed margin below `nlimit`.
* **wasmtime-py bump.** A new `wat2wasm` may change the committed bytes: the match test fails loudly
  and the bytes are regenerated by review.

**Not doing** (over-engineering list)
* no Python collector fallback, no C collector (WAT fits), no generational, incremental or concurrent
  collection;
* no large-object space, no `madvise` release, no shrinking, no compressed references (Q2);
* no liveness (step 7), no exceptions in the heap and no arena removal (step 6), no inline display
  test for function types;
* no root-registration framework or plug-in "root providers": one gather function with one loop per
  class;
* no separate memory for the collector's buffer or stack; no hash table unless D6 picks it; no
  `alloc` export unless D7 (a);
* no handle release, scopes or generations (phase 6);
* no new per-OS code (D47 rows: none; `commit_range` uses the existing `_commit`);
* no change to the code of any module without a function-subtype site (D35);
* no optimisation of the gather or of the entry path without a measurement that shows a collection's
  Python part dominating.

**Invariants relied on**
* I1-I4: references are never pinned; the operand stack is in slots at every call; marked slots
  always hold valid words; nothing is kept across a call.
* The B1 rule: a nested frame starts at `slots + 8·max(n, m)`.
* The exit record and walkable frames (D56).
* Records never move.
* Objects are 8-aligned, at least 8 bytes, with bits 0 while wasm runs.
* Every field is written at allocation (no zeroing).
* u32 references are zero-extended in u64 slots, table and global words.
* One thread per store.
* Instantiation never collects (now enforced).
