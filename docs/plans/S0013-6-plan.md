## 1. What exists today

* **The arena.** `_StoreStacks` (`targets/jit/common/instance.py:242-260`) keeps `exn` (3 u64 words:
  the pending exnref, the arena cursor, the arena limit) and `chunks` of `ARENA_WORDS = 8192`
  (`instance.py:155`). `_refill_service` (`instance.py:397-413`) is context word 11.
  `Instance.__init__` writes words 10-13 into every context (`instance.py:729-733`).
* **`throw`** is a backend method on both architectures:
  * `x86_64/backend.py:1359-1387` and `aarch64/backend.py:1057-1086`;
  * it bumps `{tag identity, payload words in slot form}` from the arena and calls `EXN_REFILL` when
    the chunk is full;
  * the core calls it from `common/compiler.py:804-813`, with the refill's site at `h0+n+1`.
* **The pads.** `landing_pads` (`compiler.py:781-802`) uses `exn_match`, `exn_field` and `exn_load`.
  In each backend (`x86_64/backend.py:1335-1357`, `aarch64/backend.py:1031-1055`) they read the
  pending word and then raw 8-byte words of the object.
* **`throw_ref`** (`x86_64/backend.py:1389`, `aarch64/backend.py:1088`) null-checks, writes the
  pending word, sets status 14 and jumps to `f.error`.
* **What the collector sees of exceptions.**
  * `_root` (`frontend/validate.py:157-159`) is "any or extern hierarchy". So exnref slots are not
    in the maps, exnref fields are 8 bytes (`gc.storage_size`, `targets/jit/common/gc.py:84-88`)
    and are not traced, and exnref tables have `refs` False (`instance.py:1102`).
  * The gatherer scans the arena by tag (`common/collect.py:103-114`).
* **The heap and the GC group.** Only a module with `gc.uses_gc` gets them
  (`common/compiler.py:263`; `instance.py:742-747`).
  * RTT words come from `gc.rtts`: struct and array types only (`gc.py:198-200`).
  * A record is keyed by `types.key` in `GcHeap.records` (`common/heap.py:73-110`). Since 5.6 a
    function type's own kind-3 record is in the same dict, under the same key.
* **The collector module** (`runtime/gc/collector.wat`):
  * `$size` accepts kind 1 or 2 only, and anything else is `unreachable` (`collector.wat:62-91`);
  * a struct's traced fields are 4-byte words at the record's offsets;
  * an array is traced only when it has `nrefs = 1` and element size 4 (`collector.wat:182-194`).
* **The host.** An `ExnRef(addr, store)` (`instance.py:173-178`) carries an arena address;
  `to_raw` and `from_raw` handle `EXN` at `instance.py:277-279` and `338-339`. `_uncaught`
  (`instance.py:843-856`) reads the payload in slot form.

## 2. Design

### 2.1 The object and the tag type-info record (brief item 1)
* **Layout.** An exception object is a struct of the synthetic fields `(i64 identity, p0, p1, ...)`,
  laid out by `gc.struct_layout` (`gc.py:91-100`):
  * the header (record offset, collector bits) at 0;
  * the u64 tag identity at 8, which is the field's natural alignment;
  * the parameters from 16 in declaration order, at their natural alignment: `i32`/`f32` 4,
    `i64`/`f64` 8, `v128` 16 (unaligned access, D41), an any-, extern- or exn-hierarchy reference 4,
    a `funcref` 8;
  * the size rounded up to 8.

  One new helper, `gc.exn_layout(mod, params) -> (offsets, size)` (~6 lines), is used by the throw
  lowering, the pads, the record and `_uncaught`, so the layout is written once (LESSONS 41).
  Equivalent tag types give the same layout in every module, because `storage_size` depends only
  on the hierarchy.
* **The record** is a kind-1 struct record (D2):
  * `final`, depth 0, display `[itself]`;
  * the size from `exn_layout`;
  * the traced offsets: the parameters with `_root` (any, extern and, from 6.2, exn);
  * written by a new `GcHeap.exn_rtt(mod, ti)` (~18 lines beside `rtt`, `heap.py:73`), and
    registered in `offsets` and `kind` like any object record (the walk check and the verifier).
* **The key** is `"exn " + types.key(mod, ti)`, where `ti` is the tag's function type.
  * There is one record per canonical tag type per store, not per tag (D3).
  * Without the prefix the key would collide with that function type's own kind-3 record (5.6,
    `heap.py:97-106`), and the collector would trap on kind 3 and lose the store. A test and a
    mutation cover this (6.4).
  * `types.key` itself does not change. A reviewer reads this anyway, since it touches type identity.
* **Identity is per process, as now.** `_TAG_IDS` (`instance.py:156`) is a u64 that is never reused.
  * Context tag words are unchanged (`instance.py:1085-1086`).
  * An imported tag keeps the exporter's `Tag`, so it has the exporter's identity.
  * The importer writes its own record for a thrown imported tag. Because the canonical type is
    equal (link checks equivalence), so is the key, and so is the offset.
  * A tag of another store is refused as today (`instance.py:1035`).

### 2.2 The heap and the GC group for exception modules (brief item 5)
* **The predicate.** A new `gc.needs_heap(mod)`, true when `uses_gc(mod)` or the module needs the
  heap for exceptions: the spec's set (`throw`, `throw_ref`, `try_table`), or D6's narrower one. It
  replaces `uses_gc` in the layout (`compiler.py:263`) only. `unsupported()` keeps `uses_gc`, so a
  backend's claim does not change.
* **The context** of such a module has (D4):
  * the heap's two words after its memories;
  * the GC group's 8 service words, after the tags;
  * the RTT words: struct and array types as today, then one word per tag the module throws;
  * the `IS_SUBTYPE` record, zero unless there is a function-subtype site.

  The thrown tags' records come from `Compiled.rtts` gaining entries for tags (a separate list
  `Compiled.thrown`, its words after the type RTTs; `Layout.rtts` counts both). In a GC module
  that also throws, `IS_SUBTYPE` moves by the number of thrown tags. That module's code changes
  anyway.
* **The store.** `GcHeap(store)` is made at the first such instance (`instance.py:742-747`, under
  the new predicate), with the 4 GiB + 32 MiB reservation and the header page; guard mode
  registers it (`instance.py:1056-1057`).
  * The tag record commits the first type-info page at instantiation, so a store that never throws
    commits **128 KiB, not the 64 KiB** S0013 Q7 says. Spec text to fix (section 3).
  * The semispaces are committed at the first `throw` (`GcHeap.room`: `_grow` on `cap == 0`).
  * The collector instance is made at the first collection, as today (`collect.py:31-55`).

### 2.3 `throw` as an allocation (brief item 2)
`gc.throw(fn, pc, t)`, ~30 lines, replacing `compiler.py:804-813`. It is `struct_new`'s shape
(`gc.py:333-347`):
1. `flush()`. With `h = len(st)`, the payload is in slots `[h0, h)`, `h0 = h - n` (v128 two slots).
2. `alloc(fn, pc, rtt_word, Imm(size), h)`. `alloc` takes the RTT word instead of a type index:
   3 lines, and the struct and array callers pass `layout.rtt(m.rtts[ti])`.
   * Its scratch slots are `rtt` at h, `new` at h+1 and ALLOC's argument at h+2, the topmost.
   * Its cold path is one `call_host(ALLOC)` safepoint with `keep = h + 3` and `top = h`
     (`gc.py:259-273`).
3. The payload stores: `_set(fn, p, TOS, off, Slot(L + h0 + k))` per parameter, reading every
   operand from its slot after the allocation (I4).
4. The identity:
   * `move(Slot(L+h+1), TOS)` (the dead `new` slot);
   * `ctx_load(TOS, layout.tag(t))`;
   * `store(8, Slot(L+h+1), 8, TOS, heap)`;
   * `move(TOS, Slot(L+h+1))`.

   The core names only `tos`, and the identity is a context word, not an operand.
5. **`throw_ref`'s tail, from existing methods:**
   * `ctx_store(EXCEPTION, TOS, indirect=True)` (the pending word gets the zero-extended u32);
   * `move(TOS, Imm(14))`;
   * `jump(f.error)`.

   tos is the status register on both architectures (`x86_64/backend.py:91`,
   `aarch64/backend.py:79`). No null test is needed: the object is fresh.
6. `del st[h0:]`; `dead = True`.

**B1 and the payload across a collection.**
* Every slot read after the ALLOC call is at h+2 or lower: the payload, `rtt` (the retry) and
  `new` (step 4, written after the call). ALLOC's argument is the topmost slot, so the
  `fn.hi <= keep` assertion (`compiler.py:353-354`) holds by construction. Step 4 takes `new`
  again through `scratch()`, after the site is recorded.
* The site's map is `lmask | ops << L` over `[0, h+3)`:
  * `ops` is the validator's mask at `throw`'s pc (0x08 is in `_SAFEPOINTS`,
    `validate.py:153`), taken before the pop, so it covers the payload;
  * with `_root` extended in 6.2, an anyref, externref or exnref payload slot is marked and
    rewritten by the collection;
  * a `funcref`, `v128` or number is not marked: records do not move.
* The object offset never crosses the call. The retry re-reads the cursor, and `tos` is computed
  after it.
* An ALLOC failure (MemoryError, status 13) goes to `f.error` like a `struct.new`'s does.
  * A pad passes every status but 14 (`landing`), so `catch_all` cannot catch "GC heap out of
    memory".
  * Under stress every throw collects. With less than 4 KiB of value stack left a throw then traps
    `STACK_OVERFLOW` (the D61 deviation now covers `throw` too; the new decision records it).

### 2.4 Landing pads (D1)
D1 (b), recommended, lowers the pad in the core with existing D39 methods. At a pad the status is
known to be 14 after `landing` (`compiler.py:784`), so `tos` may be used. Per clause with a tag:
* the pending offset: `ctx_load(TOS, EXCEPTION, indirect=True)`;
* the identity: `load(8, TOS ← [TOS + 8], heap)`;
* `move(S, TOS)`, then `ctx_load(TOS, layout.tag(tag))`, then `cmp_branch("ne", S, TOS, miss, wide)`;
* per parameter: `ctx_load` the pending offset again, then `load` (or `simd` load for v128) at its
  offset into `Slot(c.dst + k)`;
* `catch_ref`: `ctx_load(TOS, EXCEPTION, True)` into `Slot(c.dst + n)`.

Before every `jump(outer)`, `move(TOS, Imm(14))`: the next pad's `landing` and the epilogue read
the status.

**The scratch slot S** is `Slot(L + try.h)`, the try_table's entry height, recorded in
`try_table()` (`compiler.py:769`).
* Every slot from there up belongs to the abandoned body, so it is dead at the pad.
* A catch label is outside the try_table, so `c.dst <= try.h`. Payload slots written after a match
  may overlap S. They are written only after the compare, and the branch to `c` then kills
  everything above `c.dst + n`. A miss writes nothing but S, so a later clause's label sees the
  enclosing stack intact.
* `maxh` is raised to `max(try.h + 1, c.dst + n + 1 + simd scratch)` (LESSONS 108: whoever writes a
  slot reserves it).

Every heap read is an ordinary checked `load` on the hidden memory: an explicit check or a guard
fault point, as Q8 (a) asks. `exn_match`, `exn_field` and `exn_load` leave the D39 interface with
`throw`; `landing` and `throw_ref` stay.

### 2.5 `exnref` as a u32 heap reference everywhere (brief item 3)
* **One predicate.** `_root` (`validate.py:157`) becomes `top(...) in (ANY, EXTERN, EXN)`, with its
  docstring "what the collector must find". Every user then follows:
  * the validator's call-site masks (`validate.py:599`; `anyext` is set for exnref types too,
    `validate.py:171,187`);
  * the local maps (`compiler.py:344`);
  * `storage_size`: exnref 4 bytes, so struct fields and array elements of exnref are u32 and
    traced, and an exnref array has element size 4 and `nrefs = 1`, the path `collector.wat`
    already traces;
  * the records' traced offsets (`heap.py:85,95`);
  * the gatherer's globals and segments (`collect.py:91,99`);
  * `Table.refs` (`instance.py:1102`).

  A second "traced" predicate beside `_root` would drift (LESSONS 41), so there is none. `pyc` does
  not read the masks.
* **Values.** Slots, locals, globals and table words hold the offset zero-extended to 64 bits
  (LESSONS 5).
  * `catch_ref` and `catch_all_ref` read it with a 64-bit `ctx_load` of the pending word, which
    `throw` and `throw_ref` wrote from zero-extended words.
  * Fields are 4-byte loads and stores (`_field`/`_set`, unchanged).
  * `throw_ref`'s null test stays 64-bit: harmless.
* **The pending word** (`st.exn[0]`, word 10's target) holds 0 or a u32 offset. It is gathered as
  one more root run (D7: a defence, retaining at most the last exception thrown).
* **The host boundary** (D5):
  * `ExnRef(index, store)`: an entry of `st.gc_handles`, shared with `GcRef` in `st.gcrefs`, which
    `collect.py:193` already re-keys after a collection (B5);
  * `from_raw(EXN, r)` makes or finds the handle;
  * `to_raw(EXN, v)` checks `isinstance(v, ExnRef) and gcrefs.get(gc_handles[v.index]) is v`,
    else `TypeError` (LESSONS 35).
* **Uncaught payloads.** `_uncaught` reads the pending offset, the identity at `+8` (through
  `st.tags`), and each parameter at its `exn_layout` offset in the heap, with its storage size;
  `from_raw` then converts the references.
  * It runs in `_error`, right after the entry returns and before any wasm or collection can run
    (`instance.py:836-837`).
  * After it, the host holds only handles (rooted), never the raw offset.

### 2.6 Removing the arena (brief item 4)
* **Removed:**
  * `ARENA_WORDS`, `chunks`, `new_chunk` and `refill` (`instance.py:155,246-260`);
  * `_refill_service` (`instance.py:397-413`);
  * the writes of words 11-13 (`instance.py:729-733`; `exn` becomes one word);
  * both backends' `throw`, plus `exn_*` under D1 (b), and their imports of
    `EXN_REFILL`/`ARENA_*`;
  * the Protocol lines (`common/backend.py:202-207`);
  * the arena scan in `_gather` (`collect.py:103-114`).
* **The walk and the gatherer** no longer have:
  * the refill frames, which were host calls that did not set the frame base, a B1 exception
    ARTIFACT.md names;
  * the arena payload runs;
  * the `_checked` wrapper of the refill.

  They gain the pending-word run. Nothing else changes: exception objects are reached from slots,
  globals, tables and other objects like any object.
* **Context words 11-13 become reserved and zero.** `context.py:18` keeps `EXCEPTION = 10` and
  drops the other three names; the comment says "11-13 reserved, zero (S0013 step 6)".
* **No version bump.** S0013 Q5's decision (maintainer, 2026-11-06) covers it explicitly: "Step
  6's change of words 11-13 and of the exnref encoding follows from the Q7 decision and is
  recorded under the same amendment".
  * The precedent is 5.6's word 7: `FUNC_SUBTYPE` reserved and zero, `IS_SUBTYPE` appended, v1
    amended without a bump (D61).
  * No artifact file exists (ARTIFACT.md part 2 is written by ROADMAP "Next" item 6).
  * The hard rule's test, as in 5.6, is a test that words 11-13 are zero in every context of a
    store and that no compiled spec module's code names them. It spies on
    `ctx_load`/`ctx_store`/`call_host` words, as `tests/jit/test_gc_subtype.py:123-151` does for
    word 7.

## 3. Spec text that contradicts the code (to fix in S0013 with the step)

1. **The record kind.** Q7 says "One type-info record per tag type (kind `exn`)", but
   `collector.wat` traps on any kind but 1 and 2, and so would `gcverify.py:42-49`. D2 (a) keeps
   kind 1, and the text changes.
2. **The landing-pad methods.** Q7 and the plan-of-steps row say `exn_match`, `exn_field` and
   `exn_load` "change their bodies" in both backends, with the budget "x86-64 ~60, aarch64 ~60".
   Under D1 (b) they are removed and the per-architecture lines are negative. The text follows D1.
3. **The commit size.** "A store that never throws commits 64 KiB": it is 128 KiB, the header page
   plus the first type-info page (2.2).
4. **The pending word as a verify check.** "Roots and the collector" says the pending word is a
   root "checked by the verify switch". That stays true (it is in the runs, so `gcverify.check`
   validates it), but no test can see the root itself (LESSONS 105). The text gets "a defence, not
   a test target".
5. **"One RTT word per tag type it throws"** (Context ABI): the plan gives one word per thrown tag
   (equal types share the record, not the word). The text changes to "per tag it throws".
6. **The current code and tests that change:**
   * ARTIFACT.md "Host functions" names `EXN_REFILL` as the one host call that does not set the
     frame base. The sentence goes.
   * `walk.valid`'s docstring (`walk.py:123`) and `storage_size`'s ("funcref and exnref 8") need
     new text.
   * `tests/jit/test_gc_collect.py:389` asserts that exnref tables are *not* roots. It is inverted.

## 4. Decisions for the maintainer

**D1. Where the landing pad reads the object.**
* (a) **The spec's text.** `exn_match`, `exn_field` and `exn_load` stay backend methods and gain the
  heap's memory word. They add the heap base to the pending offset and read raw, about +12 lines
  per backend.
  * Those reads are unchecked: in explicit mode no bounds check, in guard mode no fault point.
  * A broken invariant (a stale pending offset) then crashes the process instead of trapping. That
    is Q8's hole again, on a path Q8 (a) wanted checked.
* (b) **In the core over existing D39 methods** (2.4): `ctx_load` (indirect), `load`/`simd` on the
  hidden memory, `cmp_branch`, and `move(TOS, 14)` before each jump to `outer`.
  * Core about +35 lines. Backends lose `exn_match`/`exn_field`/`exn_load` (about −25 lines each)
    besides `throw`.
  * Every read is checked, and aarch64 is at parity by construction (Q9 (a), D53).
  * Cost: a few more instructions in cold pad code. D39's note "the status register is preserved
    at a pad" becomes "re-made as 14 before `outer`", and a mutation checks it.

**Recommend (b).** It is the same D39 amendment as the spec's in kind (S0012's methods change), but
it shrinks the interface instead of widening two backends with an unchecked read.

**D2. The record kind of an exception object.**
* (a) **Kind 1 (struct)**, the identity an i64 first field. No change to `collector.wasm` (trusted
  code, R3), to its match test or to `gcverify`. An exception object is never in the any
  hierarchy, so no cast can confuse it with a struct.
* (b) **A new kind 4 `exn`.** `$size` and `finish` in `collector.wat`, the committed `.wasm`
  regenerated, `gcverify`, the 5.2 module tests and a reviewer of the module: about +40 lines and
  a new trusted-code review, for a distinction nothing reads.

**Recommend (a).**

**D3. How the record is keyed, and the tag identity.**
* (a) **One record per canonical tag type per store**, key `"exn " + types.key`. The identity stays
  the process-wide u64 in the object at 8. An imported tag carries the exporter's identity and
  gets an equal record (2.1).
* (b) **One record per tag**, with the identity in the record. Objects are 8 bytes smaller, but
  `exn_match` needs two dependent loads (the header, then the record), records grow with tags, not
  types, and Q7's object text changes.

**Recommend (a)**, Q7 as written.

**D4. The context of an exception-only module.**
* (a) **The full GC group** (the spec's): 8 service words (only `ALLOC` used), the RTT words, then
  the 3-word `IS_SUBTYPE` record (zero). One layout rule for every heap module; 11 unused words.
* (b) **A reduced group**: the heap words, `ALLOC` and the tag RTT words. That is a second
  `Layout` shape and a second set of offsets in ARTIFACT.md, to save 11 words per context.

**Recommend (a).**

**D5. The host's `ExnRef`.**
* (a) It keeps its class and becomes a handle: `index` into `gc_handles` (instead of `addr`),
  sharing `gcrefs` and its B5 re-key.
* (b) A `GcRef` with `kind="exn"`. Tests and the runner check `isinstance(..., ExnRef)`, and the
  public shape is phase 6's, so (b) changes a name for nothing.

**Recommend (a).**

**D6. Which instructions give a module the heap.**
* (a) **The spec's**: any of `throw`, `throw_ref`, `try_table`.
* (b) **Only what reads or allocates in the heap**: `throw`, or a `try_table` with a `catch` or
  `catch_ref` clause. A module with only `throw_ref` and `catch_all(_ref)` (cleanups) reads the
  pending word alone. It keeps today's layout and code, and its store reserves no heap.

Same lines either way.

**Recommend (b)**, which is smaller in the D35 diff and in reservations. (a) if the maintainer
prefers the spec's simpler rule.

**D7. The pending word as a root.**
* (a) **The spec's: a root.** It holds 0 or the last thrown object, which stays valid because the
  root keeps it forwarded. Cost: at most one dead exception retained per store.
* (b) **Not a root, cleared after reading.** That is a store in every pad and at the entry, so pad
  code grows. A broken invariant (a collection in flight) would then read a stale offset instead
  of a valid object.

No mutation can tell (a) from removing the root while the invariant holds (LESSONS 105), so it is
listed as a defence.

**Recommend (a).**

Not a decision: **the ABI version.** It is amended without a bump, under S0013 Q5's existing
approval (2.6). If the maintainer now wants a bump instead, it is a separate step (the serializer
does not exist).

## 5. Identity (D35; brief item 6)

| 6.3 | none (the deleted methods are no longer called after 6.2) | none | everything |

**Proof.**
1. Two fresh, empty scratch directories (LESSONS 114): `git archive` of the base into one, and of
   HEAD plus the working-tree diff into the other (`src tests tools poc/in`).

4. A scratch classifier lists, per spec module, whether it has exception instructions, exnref

5. Report the counts per column and set. The collector module is not in the lists:
   `tools/isa_all.py` covers it, and it has no exception instruction.

## 6. Tests and mutations (brief item 7)

### Tests
New tests go in `tests/jit/test_exceptions.py` (layout, host, pads), `tests/jit/test_gc_roots.py`
(roots) and `tests/jit/test_gc_memory.py` (churn). They run on the machine's JIT and under QEMU
(except the memory test, jit job only). Each forces collections with STRESS + POISON + VERIFY and
checks values and identities after them (the payload's tag and values, or `ref.eq` on any-hierarchy
payloads).

* **t1, layout**: the object bytes of a throw of `(i32 f32 i64 f64 v128 anyref funcref exnref
  externref)` at `exn_layout`'s offsets; the identity at 8; the record has kind 1, final, its size,
  and the traced offsets of the four references (not the funcref).
* **t2, a throw whose allocation collects**: payloads holding an anyref struct, an externref host
  value and an exnref; caught one frame up and three frames up, with pins live (LESSONS 2).

## 11. Risks, and what this step does NOT do (brief item 9)

**Risks**
* **The representation switch is all or nothing (6.2).** An exnref slot marked while it still held
  an arena address would trap in the collector (a nonzero high half, `collector.wat:142`). So the
  `_root` change and the heap `throw` land in one sub-step, and 6.1 changes no value.
* **Pad code re-makes the status (D1 (b)).** A missed `move(TOS, 14)` turns an exception into
  another status. M10 and t9 check it.
* **Exception-only stores reserve 4 GiB + 32 MiB** of address space and register it with the guard
  handler. Instantiation cost is measured (section 7). D6 (b) narrows which stores pay.
* **New deviations** for the decision:
  * a throw with less than 4 KiB of value stack left traps `STACK_OVERFLOW` when it must collect;
  * a throw past the live limit is "GC heap out of memory", where the arena grew without bound.
* **Front-end change.** `_root` gains EXN, so modules with exnref types get call-site masks
  computed in validation, a cost of the order of the existing masks. `pyc` is unaffected.
* **Trusted code.** The collector module and `gcverify` do not change (D2 (a)). Exception objects
  enter their struct path.

**Not doing**
* no liveness (step 7); no final review (step 8);
* no change to `collector.wasm`, no new record kind, no `alloc` export;
* no static catch as a plain jump, no `throw` fast-path tuning without a measurement;
* no change to `pyc`, the runner or status-14 propagation;
* no public `Exn`/`Tag` API and no host-thrown exceptions (phase 6); no handle release;
* no per-OS code (D47 rows: none); no artifact serializer; no version bump.

**Invariants relied on**
* I1-I4 (S0013): references never pinned (`choose_pins` takes `i32`/`i64` only, so exnref locals
  are not pinned); the operand stack in slots at every call; marked slots valid; nothing kept
  across a call.
* B1: a nested frame starts at `slots + 8·max(n, m)`; ALLOC's argument is the topmost slot read.
* Between a `throw` and its pad or entry only epilogues run: no allocation, so no collection.
* tos is the status register on both architectures, and a pad is entered only with status 14
  after `landing`.
* u32 references are zero-extended in u64 slots, globals, table words and the pending word.
* Records never move; objects are 8-aligned, every field written at allocation (poison-safe).
* Equivalent tag types have equal layouts and keys in every module of the store.
* One thread per store.
